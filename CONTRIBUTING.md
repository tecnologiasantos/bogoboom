# Como contribuir

1. **Escolha uma issue** do milestone atual. Comente que vai pegar. Issue nova? Use um dos modelos.
2. **Crie uma branch** a partir da `main`: `feature/<assunto-curto>` ou `fix/<assunto-curto>`.
3. **Faça mudanças pequenas.** Um pull request resolve uma coisa e cita a issue (`Closes #123`).
4. **Abra o pull request** e peça revisão. A `main` não recebe commit direto.
5. **Nunca coloque segredo no código:** senhas, chaves, tokens e `.env` ficam fora do git. O repositório bloqueia commits com segredos (secret scanning e push protection). Se um segredo vazar, avise na hora e revogue; apagar o commit não basta.

## Idiomas

- Issues, documentação e textos para a equipe: português.
- Código, nomes de arquivo, commits e comentários técnicos: inglês.
- Textos do produto: sempre em inglês, espanhol e português.

## Etiquetas

`area:*` diz onde mexe (frontend, backend, infra, growth, legal, hr, agency, newcomer, ai), `type:*` diz o tipo (feature, docs, security, research) e `priority:P0` a `P2` diz a urgência. `mvp` marca o que entra no primeiro lançamento.

## Dados pessoais

Este repositório é público. Listas de contatos (por exemplo, o cadastro de imobiliárias de Bogotá), documentos de usuários e qualquer dado pessoal ficam fora do repositório.
